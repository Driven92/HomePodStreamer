# HomePod Streamer（Windows → HomePod 系统声音投送）

把 Windows 电脑正在播放的声音，通过 AirPlay/RAOP 实时投到 HomePod / 支持 AirPlay 的音箱。

## 为什么不用 TuneBlade / AirParrot？
TuneBlade（2018 最终版）和 AirParrot 3（2022）都已停更。当 HomePod 升级到新固件
（本机实测为 homeOS 27.0 / AirTunes 980.77.2）后，它们的 AirPlay 会话握手层会失败、连不上。
本工具底层改用 **pyatv**——一个仍在积极维护的 Apple 设备协议栈，已实测可正常与
固件 27.0 的 HomePod 完成 RAOP 握手并推音频流。

## 安装（源码运行）
在 Python 3.13 虚拟环境中：
```
pip install -r requirements.txt
```
依赖说明：
- `pyatv`：AirPlay/RAOP 协议（自带 RTP 打包与 ChaCha20 加密，不需要 ffmpeg）
- `srptools < 2`：**必须锁 1.x**。2.0.0 把 `SRPClientSession(ctx, private)` 改成了仅限
  关键字参数，而 pyatv 0.18.0 仍按位置参数调用，装上 2.x 后每次连接都抛
  `TypeError: SRPClientSession.__init__() takes 2 positional arguments but 3 were given`
  → 点了投送没声音也没报错（v1.2.0 踩过这个坑）。
- `soundcard`：用 WASAPI 环回抓取“系统正在播放的声音”，自动重采样到 44.1kHz（CFFI 直连，正确处理 WAVE_FORMAT_EXTENSIBLE）
- `numpy`：采集到的浮点音频转 16-bit PCM 时用到
- `PyQt6`：图形界面与原生系统托盘（自带 Qt 运行时，无需系统 Tk）

## 使用
### 图形界面（推荐）
```
python -m homepod_streamer
```
- 启动即自动扫描；点设备行右侧的圆形 **▶** 直接开始投送，再点一次（变成绿色 **■**）即断开。
  点行内其它位置只是选中，不会误连。
- “音量”滑块实时调节 HomePod 音量（拖动时合并抖动，停下 120ms 才下发）。
- “延迟缓冲”分段控件：0.25 ~ 1.2 秒可选，**越小延迟越低**（改动会立即重连生效）。
- “有声测试”向选中的音箱播放 8 秒提示音。**它不经过系统声音采集**——能听到就说明
  从握手到音箱解码整条链路是通的，听不到则是连接或音箱本身的问题，可以据此快速定位。
- 顶部卡片显示当前投送目标与跳动频谱；没有连接时显示“待连接”。
- 右上角 **✕** 关闭窗口 = **最小化到系统托盘**（右键托盘图标可“显示窗口 / 连接上次设备 /
  断开 / 开机自启 / 关于 / 退出”），不会真正退出；**－** 则最小化到任务栏。
- “开机自动启动”开关：开启即把本程序写入当前用户开机启动项（注册表 `HKCU\...\Run`），
  下次开机自动以最小化 + 托盘方式启动并连回上次使用的设备。

### 命令行
```
python -m homepod_streamer --scan                 # 列出局域网可投设备
python -m homepod_streamer --name 客厅            # 投到名为“客厅”的设备
python -m homepod_streamer --test --name 客厅     # 播放 8 秒测试提示音（有声），验证链路
python -m homepod_streamer --autostart on|off     # 开/关开机自启（写注册表，立即退出）
python -m homepod_streamer --minimized            # 隐藏窗口、常驻托盘、自动连上次设备
python -m homepod_streamer --name 客厅 --latency 0.4   # 指定输出缓冲（秒）
python -m homepod_streamer --version              # 打印版本号
```

设计要点：
- **不依赖任何图片资源**：喇叭图标、滑块、开关、频谱条、刷新/关闭图标全部用 `QPainter`

- **无边框窗口 + 圆角 + 右上角光晕**，标题栏可拖动；关闭按钮 = 最小化到托盘。
- **窗口高度跟随设备数量**（0 个 → 空状态提示，1~3 个自适应，更多则滚动）。
- 换肤只需改 `ui.py` 顶部的调色板常量（`ACCENT` / `ACCENT_2` / `CARD` / `BG_*` 等）。


## 延迟说明

整条链路的延迟 ≈ **输出缓冲（latency）+ 音箱解码渲染（约 70ms）+ 网络**。

pyatv 默认把输出缓冲设成 `22050 + 采样率 = 66150` 帧，即 **1.5 秒**，这是延迟的大头。
本工具默认压到 **0.5 秒**，并额外修掉了两处会“悄悄叠加”的缓冲：

| 环节 | 默认/优化前 | 现状 |
|---|---|---|
| RAOP 输出缓冲 | 1.5 s | **0.5 s**（可调 0.25~1.5） |
| 握手期积压的旧音频 | 0.5~2 s（永久叠加） | 开播前丢弃，**0** |
| WASAPI 客户端缓冲 | 2048 帧 ≈ 46 ms | 512 帧 ≈ **12 ms** |
| 音箱解码渲染 | 70 ms | 70 ms（设备固有） |
| 合计 | 约 2~4 秒 | **约 0.6 秒** |

调整建议：局域网稳定时 0.4 甚至 0.25 都能用；若出现断续/卡顿，就往大调一档
（0.8 / 1.2）。改动在界面上即时生效（会自动重连一次）。

## 版本号

版本号只在 `homepod_streamer/version.py` 里维护一处，改完自动生效到：

- **窗口标题**：`HomePod Streamer  v1.1.0`
- **窗口底部**灰字标签：`版本 v1.1.0 · 打包版/源码版`
- **托盘右键菜单 → 关于**：显示版本、该版本说明、当前延迟缓冲、程序所在路径
- **exe 属性**：资源管理器里“属性 → 详细信息 → 产品版本”
- **命令行**：`--version`
- **发布压缩包名**：`HomePodStreamer-v1.1.0-win64.zip`

版本规则为语义化 `主.次.修订`：主版本＝不兼容大改，次版本＝加功能，修订号＝修 bug。

## 打包成 exe
已随附一键打包脚本（需先 `pip install pyinstaller`）：
```
python build_exe.py            # 打包 + 生成压缩包
python build_exe.py --no-zip   # 只打包，不压缩
python build_exe.py --no-clean # 复用编译缓存，打包更快
```

产物（**单目录模式**）：
```
dist/HomePodStreamer/HomePodStreamer.exe        ← 直接双击运行
dist/HomePodStreamer-v<版本>-win64.zip          ← 整个文件夹的压缩包，用于分发/备份
```

> **为什么用单目录而不是单文件 exe**：单文件版每次启动都要把约 160 MB 内容解压到
> `%TEMP%\_MEIxxxxxx`，启动慢、吃 C 盘，异常退出还会残留 156 MB 垃圾目录（攒几次就
> GB 级）。单目录版原地加载 DLL，**启动秒开、不写临时目录**。
>
> 代价是**不能只拷 exe**——`HomePodStreamer.exe` 必须和同级的 `_internal\` 目录在一起。
> 移动/备份时请整个文件夹一起拷（或直接用生成的 zip）。
>
> 打包只收 `PyQt6.QtWidgets/QtCore/QtGui`，显式排除 QtQuick / Qml / Quick3D / Designer /
> Pdf / QtMultimedia（含自带 FFmpeg）等未使用模块——PyQt6 整包解压要 215 MB，
> 而本程序只用到其中很小一部分。

## 工作原理
1. `soundcard` 以 WASAPI 环回模式采集默认输出设备（即“正在播放的声音”），返回 44.1kHz / 2ch / float32。
2. 在采集线程内转换成 16-bit 小端 PCM，经线程安全队列交给推流引擎。
3. 推流引擎绕过 pyatv 内置的 miniaudio 解码（`raw_source.py` 直接喂裸 PCM 给 RAOP），
   由守护事件循环内的协程把数据喂入 `StreamReader`，再交给 pyatv 完成 RTSP/RAOP 握手、
   ChaCha20 加密与 RTP 发送。
4. 延迟控制（`streamer.py` 顶部）：给 `StreamContext.reset` 挂补丁，把 pyatv 硬编码的
   1.5 秒输出缓冲改成可配置值；给 `StreamClient._stream_data` 挂补丁，在 RECORD 之后、
   正式发第一包之前丢掉握手期间积压的音频；`_feed_reader` 另有带迟滞的缓冲上限，
   防止长时间运行因两端时钟微小偏差让延迟越积越多。

## 代码结构
| 文件 | 职责 |
|---|---|
| `main.py` | 命令行入口、日志初始化、参数解析；GUI 通过 `ui.run_gui()` 延迟导入 |
| `ui.py` | 全部界面代码：调色板、自绘控件（滑块/开关/分段/频谱/图标）、设备行委托、主窗口 |
| `streamer.py` | 投送引擎：扫描设备、RAOP 握手、延迟补丁、缓冲安全阀 |
| `capture.py` | WASAPI 环回采集，float32 → int16 PCM，队列溢出丢最旧 |
| `raw_source.py` | 绕过 miniaudio 解码，直接给 pyatv 喂裸 PCM |
| `config.py` / `autostart.py` | 配置读写（`%APPDATA%/HomePodStreamer/config.json`）、开机自启注册表 |
| `version.py` | 版本号唯一来源，界面/资源/压缩包名都从它取 |

## 已知限制
- 本机默认混音格式为 48kHz / 32-bit 浮点，由 soundcard 在采集端重采样到 44.1kHz（RAOP 发送端硬编码 44.1kHz）。
- 受 Windows Proactor 事件循环 + 线程池调度影响，偶有数毫秒级抖动（日志里 `Too slow to keep up`），对音频无实质影响。
- 投送的是“系统默认输出设备的声音”；如需只投某个程序，请在 Windows“声音”设置里把该程序输出到对应设备。

## 故障排查
- GUI 列表看不到 HomePod：确认电脑与 HomePod 在同一局域网/网段；关闭 VPN。
- **点了投送、界面显示“正在投送”但完全没声音**：
  1. 先点“有声测试”。听得到 → 投送链路没问题，问题在“采集到的是什么”（见下一条）；
     听不到 → 连接/握手/音箱侧问题，看 `app.log` 里有没有 `stream_file starting`。
  2. 看界面底部状态行里的 **采集：<设备名>**。程序抓的是 **Windows 默认输出设备**的环回，
     如果系统默认输出被切到了 HDMI / S/PDIF 而声音实际在另一块声卡上，就会抓到静音。
- **日志里只有“使用输出缓冲”，没有 `stream_file starting`**：连接阶段就失败了。
  v1.2.0 曾因 `srptools 2.0.0` 改了 `SRPClientSession` 签名（pyatv 0.18.0 仍按位置参数调用）
  导致 `pyatv.connect` 必抛 `TypeError`，表现就是“点了没声音、也没任何报错”。
  已通过 `requirements.txt` 锁 `srptools<2` 修复；重装依赖后务必确认版本。
- 连上但无声音：确认 Windows 默认输出设备正确；检查 HomePod 侧“隔空播放”权限。
- 推流卡住/无 RTP：看日志里 `Sent N frames` 是否持续增长；无增长多为采集端异常（检查默认扬声器与环回权限）。
- exe 启动异常：查看 `%APPDATA%/HomePodStreamer/app.log`（仅打包后在文件中有记录）。
